# RadElement next-generation alpha

A working model of the definition layer: a knowledge graph of radiology findings,
diagnoses, elements, measurements and anatomy, with an OWL rendering used to check
that it holds together.

| | |
|---|---|
| `SHAPE.md` | what the model is made of and what it reaches |
| `MECHANISMS.md` | what each mechanism does and why |
| `evaluation/` | one dated file per evaluation run, plus an index |
| `README.md` | this file: how to run it |

Clinical content is provisional and unvalidated. Terminology codes are extracted
from `RadLex.owl` 4.3; `scripts/verify_codes.py` checks every code in the model
against the label RadLex gives it, and is the check worth running before any
release.

## Looking at it in Protégé

Open **`standalone/radcde-standalone.owl`**. One file, nothing to resolve.

Before anything else, set the renderer: **Protégé → Preferences → Renderer →
render by annotation value → `rdfs:label`**. Without it, anatomy shows as `RID1303`
instead of "upper lobe of right lung".

Then **Reasoner → HermiT → Start reasoner**.

Three things worth looking at:

**`PartSolidPulmonaryNodule`.** Look at its Equivalent To axiom: it is *pulmonary
nodule with part-solid attenuation*, so nothing about it is authored twice. Then
open `PROBE A3`, which asserts exactly that construction. After reasoning it sits
under `PartSolidPulmonaryNodule` and carries the solid-component requirement.
Yellow means inferred; turn the reasoner off and those rows disappear.

**`PROBE B1` and `PROBE E8`, read as a pair.** `B1` is a nodule that is both solid
and part-solid, and goes red: one entity cannot hold two values of a functional
property. `E8` is a part-solid nodule whose *component* is solid, and stays white.
The difference is `hasComponent`, which supplies the second entity.

**`PleuralEffusion`.** Causal and evidential edges sit side by side on one class:
pneumonia *causes* an effusion, empyema *manifests as* one.

The modular pair (`radcde-alpha.ttl` plus `radcde-anatomy.ttl` and the catalog) is
the better long-term shape, since anatomy is thrown away and regenerated on each
RadLex release while the authored layer is not.

## Probes

Open **`standalone/radcde-standalone-probes.owl`** and run the reasoner. Sixteen
deliberate test cases. Anything contradictory moves under `owl:Nothing` in red.

| Group | Expect |
|---|---|
| A (six) | classify under something informative |
| B (six) | five red; `B5` stays white, a negative control |
| C (three) | exercise an unadopted edge; only `C2` red |
| D (one) | stays white: shows the lint rules are not reasoner-enforceable |

Every probe label states what the reasoner should conclude, and **where to look for
it**, because only one of the four outcomes is visible as colour.

| outcome | where it shows |
|---|---|
| `EXPECT INCONSISTENT` | red, under `owl:Nothing` |
| `EXPECT EQUIVALENT` | yellow row in the **Equivalent To** box. Does **not** move in the tree |
| `EXPECT SUBCLASS` | yellow row in **SubClass Of**. Moves in the tree once the dropdown above it is set to **Inferred** |
| `EXPECT CONSISTENT` | stays where it is, no yellow rows |

The equivalence case is the one that looks like failure. A probe whose description
exactly restates an existing definition comes back **equivalent** to that class, and
equivalent classes are siblings, not nested — so it never appears underneath the
class it matched. `PROBE A3` restates `part-solid pulmonary nodule` and sits beside
it, not under it. Read the Description panel, not the tree.

Yellow means inferred throughout: turn the reasoner off and every yellow row
disappears. Right-click a red class → **Explain** shows which axioms made it
impossible — worth doing even when the answer is expected, since a probe can go red
for a reason you did not intend.

## Rebuilding

```bash
pip install rdflib owlready2
cd scripts
python build_anatomy.py      # RadLex.owl -> anatomy.json          (~45s first run)
python build_owl.py          # -> the two ontology modules, both formats
python build_probes.py       # -> the probe module
python build_json.py         # -> definition-graph.json and compiled/
python build_standalone.py   # -> standalone/, merged, no imports
python build_shape.py        # -> SHAPE.md
python build_mechanisms.py   # -> MECHANISMS.md
python test_reason.py        # 8 entailment checks        (needs Java)
python test_probes.py        # 25 probe checks         (needs Java)
python evaluate_graph.py     # -> evaluation/<date>.md; non-zero exit if an invariant fails
python verify_codes.py       # every RadLex code against its source label; needs RadLex.owl
python -c "import spec; print(spec.lint() or 'lint clean')"
```

`evaluate_graph.py` reports three groups. **Structure** is generic graph analysis,
restricted to the measures that mean something for a definition layer: orphans,
components, cycles in the taxonomy and partonomy, depth, tangledness, degree.
**Richness** is OntoQA-style and comparable across releases rather than meaningful
in isolation. **Invariants** are claims the model makes about itself, and a
failure there is a defect — it exits non-zero so it can gate a build.

Each run writes its own dated file rather than overwriting, because the richness
numbers are only meaningful as a series. Every run carries a trend table of the
last few.

It deliberately does not compute clustering coefficient, betweenness, eigenvector
centrality, PageRank, diameter or assortativity. All are well defined on this
graph and none would tell you anything actionable: a definition graph has almost
no triadic closure by construction, and centrality is dominated by the anatomy
root, which reflects import depth rather than anything about the model.

`build_anatomy.py` and `verify_codes.py` read `RadLex.owl`; set `OWL_SRC` at the
top of the first, or `RADLEX_OWL` in the environment for the second. The first run
parses it and caches to N-Triples, later runs reuse the cache.

`verify_codes.py` is the highest-yield check here. Fourteen codes written from
memory during the build were wrong and every one looked plausible in the file: a
code standing in for "infectious" was psoriatic arthritis, one for "rib fracture"
was a brain structure, one for "margin" was "scattered". None was catchable by
reading. It reports three bands: a code that does not resolve, a code whose label
is unrelated to what the model calls it, and a code that is right but carries a
shorter label here, which is not an error. It exits non-zero on the first two, and
skips with a message when RadLex.owl is not present, since the built artifacts
cannot answer the question on their own.

**`spec.py` is where the content lives.** Add a finding by adding a dict to
`FINDING_CLASSES` and rebuilding. Test a modelling question by adding a probe to
`build_probes.py` and seeing whether the reasoner agrees with you. `SHAPE.md` and
`MECHANISMS.md` are generated, so they cannot drift from the build.
